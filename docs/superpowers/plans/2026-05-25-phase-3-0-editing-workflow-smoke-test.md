# Phase 3.0 冒烟手测清单

> 在本地 `pnpm dev` + 真 DB 跑完一遍，全过算上线就绪。

## 准备

1. `docker-compose up -d postgres`
2. `pnpm db:migrate && pnpm db:seed:product-config`
3. `mkdir -p ./tmp/editing-nas`
4. `.env.local` 设 `EDITING_NAS_PATH=./tmp/editing-nas`
5. `pnpm dev`

## 测试步骤

### 1. 入口权限
- [ ] 用 admin 账号登录，访问 /editing → 看到 5 列看板
- [ ] 用「其他」岗位账号登录，访问 /editing → 重定向到首页

### 2. 新建任务
- [ ] 点「+ 新建任务」→ 弹窗出现
- [ ] 搜索一个真实 live_account → 下拉显示
- [ ] 选中 → 主播自动联动（若该账号有 default anchor）
- [ ] 选素材文件 → 「创建并上传」→ Toast 成功
- [ ] 看板「待剪辑」列出现新卡片

### 3. 批量派单
- [ ] hover 卡片 → checkbox 出现
- [ ] 勾选 3 张 → 底部浮动栏出现「已选 3 条」
- [ ] 下拉选剪辑师 → 「确认派单」→ 3 张卡片移动到「剪辑中」

### 4. 上传成品 + 审核
- [ ] 切换到剪辑师身份（或用 admin），点开「剪辑中」一张卡 → 抽屉打开
- [ ] 「上传成品」→ 选文件 → 状态变 review
- [ ] 切回运营，打开 review 中的卡片 → 「审核回退」填原因「字幕有误」→ 卡片回剪辑中
- [ ] 抽屉时间线显示回退事件 + 原因
- [ ] 重新上传成品 → review → 「审核通过」→ 卡片到「待发布」

### 5. 标记发布
- [ ] 点「待发布」卡片 → 抽屉 → 「标记已发布」
- [ ] 系统尝试自动绑定抖音视频
- [ ] 若失败 → 弹手填输入 → 输入测试 video_id → 卡片到「已发布」
- [ ] 抽屉显示「抖音视频」section 含 video_id 链接

### 6. 删除
- [ ] 选中 1 张「待发布」+ 1 张「已发布」→ 批量删除
- [ ] Toast: 删除 1 条，跳过 1 条（已发布不可删）

### 7. 表格视图
- [ ] 切换到「表格」tab → 看到任务列表
- [ ] 状态/产品/剪辑师列显示正确
- [ ] 停留时长 >1d 黄色，>2d 红色

### 8. 收纳
- [ ] 待剪辑列 ≥7 条 → 出现「+ 查看其余 N 条」
- [ ] 折叠「前天」分组 → 任务不显示但 count 保留
- [ ] 顶部「产品 · 捕鱼大作战」筛选 → 仅捕鱼任务可见

### 9. 权限可见性
- [ ] admin 看全部任务
- [ ] 运营 op1 只看自己负责账号 + 创建的任务
- [ ] 剪辑师只看派给自己的任务
- [ ] 「其他」岗位访问 /editing 被拦截

### 10. 事件流
- [ ] 完整生命周期任务的抽屉时间线 ≥ 5 条事件
- [ ] 含创建 / 派单 / 上传成品 / 审核 / 发布
- [ ] 审核回退事件包含 reason

## 已知遗留

- 文件存储 NAS device path 是占位（`docker-compose.yml` 里 `:/volume1/qjhy-edit`）—— 部署前需要运维确认真实路径替换
- 主播筛选 chip 是 placeholder（未实现）
- 日期范围筛选 chip 是占位（默认近 7 天硬编码）
- 视频在线预览未做（剪辑师/审核需下载本地看）
