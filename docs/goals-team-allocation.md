# 团队目标与个人运营目标

2026-10-17 已按用户确认部署 NAS，发布记录见文末。代码基线见 `.local-backups/goals-team-baseline-20261017-111617`；按用户要求没有备份数据库。

## 使用

1. 点击“新建目标”，切换“团队目标 / 个人目标”。团队目标保留原来的多指标、权重、统计口径和季度关联设置。
2. 团队负责人确定并发布团队目标后，运营选择“个人目标”，填写周期、项目、部门、负责人，再关联团队目标。系统按产品、部门及运营归属自动匹配账号。
3. 个人只填写各项指标的目标值，不再自行选指标、填权重、修改统计口径或关联季度。全部从团队继承；暂不承担的指标填0。只列出已确认口径、支持累计拆分且账号范围兼容的团队目标；有权限的管理人员也能为自己的团队草稿分配个人目标。
4. 提交保存为个人草稿，在指标明细标记“待负责人确认”。负责人在团队指标下调整个人数值；发布团队指标时默认勾选“同时发布下属个人目标”，可核对本指标下的运营和数值，也可取消勾选只发布团队指标。团队指标已经发布时，点击“发布个人目标（N）”可集中确认本指标待发布的个人目标。普通运营无发布权限时不能修改已发布目标。个人提交、调整、发布继续沿用原有填报、管理范围及发布权限，未自动修改权限配置。
5. 管理人员仍可在团队分组点击“拆分目标”，一次分配多位运营。展开团队行，再点击“小手柄流水”等指标，查看各运营在该指标下的目标、实际值和达成率。
6. 个人详情可查看账号名单。已发布的个人目标可通过“更新归属账号范围”确认更新本指标账号；更新原因和前后范围进入调整记录。

旧版未关联团队的个人运营目标，点击调整也进入该简化表单，可选择上级团队并保留原目标值。服务端逐项核对原目标的人员、周期、产品和指标；原团队已有同运营指标时拒绝重复关联，不自动合并。团队已有其他指标时一并补填，不删除原目标记录。

目标管理和首页均采用“团队 → 指标 → 运营明细”的展示层级，运营明细默认收起，不再重复展示整组个人目标卡片。团队行保留团队综合进度；个人综合达成率集中在“运营汇总”弹窗，目标管理中的个人整体调整和归档也可从该弹窗进入。个人指标行仍可查看详情、发布、删除和调整个人目标；“全部展开 / 收起”包含指标下的运营明细。筛选或权限范围内没有对应团队指标时，个人目标仍独立展示。

团队负责人只代表团队责任，不限制团队只统计负责人自己的账号。个人目标按产品、部门及运营身份匹配账号，不以负责人姓名直接作为查询条件；优先使用经纪人绑定的员工 ID，没有绑定时沿用业务看板归因，无唯一归属的账号不自动分配。

## 计算与约束

- 联动发布仅处理当前团队指标下的待确认个人目标，其他指标和已发布目标不重复发布。提交时核对团队版本、完整待发布名单及个人目标版本；目标新增、删除或数值变更后须刷新重新确认。使用同一数据库事务逐项执行现有发布校验，任意一项失败则全部回滚，每项目标分别保留发布记录。
- 首页“本月目标跟进”复用目标管理分组表格，按“项目／部门、负责人、指标进度、跟进状态”四列展示；指标和运营明细继续逐层展开，运营汇总可查看个人综合进度，管理操作进入目标管理。

- 普通运营新建时直接进入个人目标，不显示团队切换；负责人固定本人。部门管理权限（`team` 且确实管理部门）及全范围管理权限（`all`）可切换团队／个人，并在原有部门、产品和业务数据授权交集内选择运营。仍须单独具备填报、发布等操作权限；仅委托查看人员不会获得管理权限。
- 人员候选、个人团队查询、个人提交、单指标／多指标／整组调整及团队拆分均由服务端校验，不能通过改请求给其他运营填报或创建团队目标。历史未关联团队的运营个人目标仍可通过简化调整入口关联团队；列表和查看权限不扩大。

- `team_parent_id` 关联团队分组中的代表指标；原 `parent_id` 仍专用于季度拆月度，两者独立。
- 同团队、同指标的个人分配总额不能超过团队目标，可保留未分配额度。同一运营不能重复建立该团队同指标目标。
- 个人统计范围须在团队范围内；同团队同指标的个人账号不能重叠。
- 个人草稿自动使用最新运营归属。发布时由服务端固定账号 ID；普通调整目标值保留已发布范围，显式更新范围会重新统计整个目标周期。
- 团队与个人分别按各自指标权重计算进度。工作台不把个人指标再次计入团队的综合进度。
- 个人新建及调整入口仅提交团队引用、版本和个人目标值，指标定义与权重由服务端重新读取。团队修改指标权重时同步未归档个人目标，并增加版本和审计记录。已有个人目标不会在打开页面时被批量改写。
- 个人候选团队接口仅向授权范围内、账号符合团队统计范围的运营提供必要的团队定义、分配余量和自己的账号，不开放团队实际值、其他运营的个人目标或账号名单。普通目标列表和历史记录权限保持原规则。
- 当前拆分入口用于支持相加的累计指标；均值、峰值、比率、上限类目标不直接拆分。
- 捕鱼月度“达标账号数”也支持和消耗一起拆分：按运营名下互不重叠的账号独立判断、去重计数，个人继承团队的 ROI 门槛、最低消耗和指标权重，人数／账号数目标须为整数且个人分配总数不超过团队目标。账号达标数不作为跨月可累加指标，不开放季度账号数拆分或季度到月度的累计分配。
- 团队已有个人拆分后，修改团队归属、账号范围或继承口径受到保护；须先处理关联个人目标，避免已拆分目标悬空。季度口径同步同样保护已拆分的月度目标。
- 原有权限、版本冲突校验、逻辑删除和审计记录保留。员工仅能看到其有权限的目标；所属团队不可见时，个人目标单独展示。
